new Interactive demo UI segmap ui

A local page for driving the whole repo by hand: the colourised map and legend on the left, three tabs on the right. The raster and both indices load once at startup, so a question costs a second instead of the ~50 s an index build costs.

Built

  • Verbs tab — S5 query language driven by hand, with example chips. Every answer carries its region ids.
  • Solutions tab — S1–S6 as cards with their real options, output rendered exactly as the CLI renders it.
  • Ask tab — the tool-call log renders directly beneath the prose, so a claim and its evidence are read together.
  • Degrades honestly: no key returns the actionable message, not a traceback; S6 explains it has no second date.
  • Stdlib http.server, zero new dependencies, verified end-to-end on every endpoint.

Missing

  • No map interaction. The preview is a static PNG — you cannot click a region to get its id, pan, or zoom.
  • No raster switching. The tile is fixed at launch; changing it means restarting the server.
  • No file upload — you need shell access to point it at a raster.
  • Results are not exportable from the page (no CSV / GeoJSON download).
  • Single-user by construction: one global lock, no auth, localhost only.

Next

  • Click-to-identify on the preview → region id, class, area, neighbours. Cheapest large win.
  • Overlay the answer on the map — highlight the ids a verb returned instead of listing them as text.
  • A raster picker that indexes in the background with a progress line.
  • Download button per result, wired to the GeoJSON export below.

new Illustrated report generator segmap showcase

One self-contained HTML page per raster — 24 images base64-inlined, no sidecar directory — explaining all six solutions and illustrating each from the file it was pointed at. About a minute on a 67 Mpx tile with a warm cache.

Built

  • Overview, class legend, and class isolations on a ghosted basemap (roads / built / vehicles / rock / vegetation series).
  • Full-res detail crops, auto-located on the densest window per group — finds the settlement without being told where it is.
  • All four S4 products plus a dry-vs-wet difference map; the corridor passable-ground raster.
  • S1 findings boxed on the map beside the cause table; S3 triage drawn as dispatched-vs-control chips.
  • Per-solution algorithm walkthrough, worked examples, and where each one abstains.
  • Verified on two different rasters — different GSD, different class mapping.

Missing

  • S6 is explained but never demonstrated — no second date exists for any tile.
  • Static output: no zoom, no toggling a class on and off.
  • Reference object sizes for the count check are hard-coded for House/Car/BrickWall only.
  • No PDF or print stylesheet.
  • Regenerating is all-or-nothing; no per-section rebuild.

Next

  • Emit the S1 findings and S5 answers as GeoJSON alongside the page, so they open in QGIS.
  • Side-by-side mode for two rasters — the natural home for S6 once a second date lands.
  • Let the class-isolation groups be configured rather than hard-coded.

new S5 live evaluation harness out/live_ask/

The round-trip check S5's docs called for: ten analyst questions, offline ground truth first, then the model, then grade the model against the truth. Two model configurations side by side.

Built

  • Ten questions covering all six verbs plus three designed refusals and one uncovered case.
  • Offline ground truth computed and saved for every quantitative question.
  • Runner script parameterised by model and effort; raw output captured per question.
  • Confirmed the code half of the refusal contract: vehicle type, building function, and slope-without-DEM all abstain with a reason rather than returning zero.

Missing

  • blocked The model half never ran — the API key is 20 characters where a real one is ~100. All 20 calls returned 401.
  • So: no verdict on whether the planner plans, and none on whether the model relays a refusal instead of substituting a near-miss class.
  • No golden-set test — grading is manual, not a CI check.
  • Grading rubric does not yet handle model-side arithmetic (see Q3 below).

Next

  • Drop in a valid key and re-run — two commands, index is cached, everything else is staged.
  • Promote the ground truth to a golden-set pytest, so the arithmetic is checked on every commit for free.
  • Decide the Q3 rule: add a ratio verb, or permit arithmetic over quoted tool outputs.

S1 — Consistency audit built · unvalidated

Flags labels contradicting their context, slope or geometry; rolls thousands of flags into the handful of distinct facts they instance; ranks by what a reviewer's next minute is worth. On the demo tile: 2,710 findings → 62 root causes.

Built

  • Five check families, severity graded from evidence rather than a constant.
  • Roll-up to root causes with example region ids — the thing that makes 2,710 rows reviewable.
  • Ranking by severity × area0.5.
  • Coverage block printed first, stating that an unchecked class is unexamined rather than clean.
  • Abstains on slope and aspect rather than scoring against a fabricated 0.0.

Missing

  • False-positive rate is unknown. Every count is a candidate count — this is the blocking question.
  • class_distance does no work in the speck check: it returns 1.0 for every cross-superclass pair, so the check is effectively "small + enclosed".
  • Coverage is 2.0% of area on this tile — nothing to say about Rendzina, which is 65% of it.
  • Severity is not calibrated across kinds.
  • Connected components fragment badly; a boundary wobble makes two findings where a human sees one.

Next

  • Review ~50 causes by hand → a precision number. Cheapest unblock in the repo.
  • Attach a DEM — activates the two abstaining check families at a stroke.
  • Give class_distance a notion of compatible classes (grass on soil is not a contradiction). Not by adding a prior.

S2 — Confusion adjudication built · placeholder scoring

Answers "then what is it?" for a flagged region by scoring a candidate list on three evidence terms — and refusing when the evidence cannot separate them. The refusal is designed to fire often.

Built

  • Three-term scoring: context, morphology, geometry — each with its note.
  • A 0.15 margin before a SWITCH; inside it, KEEP or UNDECIDABLE, never a coin flip.
  • UNDECIDABLE-NEEDS-geological-map as a first-class verdict.
  • Full candidate table shown, so the verdict can be argued with.

Missing

  • Hand-set weights. A placeholder for a calibrated model.
  • The segmenter's own confidence is absent — highest-value missing input.
  • Shortlist recall unmeasured: if the truth is off the list, no weighting saves you.
  • UNDECIDABLE only triggers on lithology; terra rossa vs clay is arguably as unresolvable.
  • Nothing writes back. An accepted SWITCH goes nowhere.
  • Cannot express "split this region", which is sometimes the right answer.

Next

  • Get a validation confusion matrix — replaces taxonomy-derived candidates with measured ones.
  • ~500 adjudicated regions → logistic regression, which gives the calibrated probability the margin actually needs.
  • Decide the write-back path: raster edit, correction layer, or review queue.

S3 — Cost-aware detection triage built · no outcome data

Uses the cheap segmentation as a prior to decide which chips get an expensive detector. The model compiles a policy once; a deterministic scorer applies it per chip. 95% cost reduction on the demo tile.

Built

  • Three policies (vehicles / structures / oov), checked in and human-readable.
  • Pure-arithmetic scoring over the precomputed chip index — milliseconds over millions.
  • Hard-exclude list with a written rationale.
  • Mandatory control set sampled from rejected chips — the only unbiased recall signal there is.
  • Refuses to let "score captured" stand in for recall, in capitals.

Missing

  • No recall number, because no detector has run on the control set.
  • budget_frac is the wrong knob — top-K is a placeholder for a recall target.
  • The detector's cost model is unknown (per call? per megapixel?), which changes optimal chip packing entirely.
  • No spatial diversity guard — the whole budget can collapse onto one settlement.
  • Policy versioning is designed but not enforced; a stale policy fails silently.
  • Never compared against the LLM-generated policy, though the baseline is checked in and ready.

Next

  • Run any detector on the control set. Unblocks the recall number, the isotonic selector, and the whole cost argument at once.
  • Ask the detector owner for the cost model before optimising anything.
  • Cheap and testable today: LLM policy vs hand-written baseline.

S4 — Derived decision products built · units undecided

47 classes + slope + season → the raster someone actually asked for. Authored with a model, evaluated deterministically. No LLM at runtime.

Built

  • Four products: trafficability, concealment, drainage, fire_fuel.
  • Vehicle (wheeled / tracked / foot) and season modifiers.
  • Slope and roughness penalties where a DEM exists; vectorised.
  • Summary by superclass, so the shape of the answer is legible before opening the image.
  • PNG export.

Missing

  • Is 0–1 even the right output? A float with no units is hard to argue with and hard to validate. GO / SLOW-GO / NO-GO, or km/h, may be what is wanted.
  • Nobody owns the numbers. Trafficability is a vehicle × doctrine × risk decision, not a physical constant.
  • --wet is a binary switch, not a moisture model.
  • DEM resolution and smoothing window are free parameters nobody has set.
  • Line-of-sight is absent — the most-requested product.
  • No composition rule for "concealed and trafficable", which is the real question.
  • No ground-truth path for validation.

Next

  • Settle the output format with whoever consumes it before tuning a single constant.
  • Name an owner for the doctrine numbers.
  • Add LOS once a DEM exists — it needs a viewshed, not a class lookup.

S5 — Natural-language querying verbs solid · planner untested

Six verbs answering quantitative questions in code, so no model ever does arithmetic over a big table. The verbs are the tool surface a model is given — having them exist first is what keeps the model out of the numbers.

Built

  • Six verbs: describe, find, count, area, distance, corridor.
  • distance is true pixel-to-pixel and returns both endpoints, so it is checkable on the map.
  • Evidence in every result — the region or component ids it was computed from.
  • Four distinct statuses: ok, empty (a measured zero), unanswerable, error.
  • Refusals enforced in code, not trusted to the prompt.
  • Typed Anthropic tool definitions, prompt-cache-friendly ordering.

Missing

  • untested The planner. Not one live call has succeeded — the key is invalid.
  • count does not count objects on every map. Measured: the largest House component on the demo tile holds 64% of all House area — one settlement, one "building".
  • No arithmetic verb. "How does dirt compare to paved" forces the model to divide, producing a number no tool returned.
  • Pixel coordinates only. No lat/lon or GeoJSON — ids are checkable against the index but not against anyone's map.
  • near is still centroid-based; distance already does it properly.
  • Single-tile only. No AOI-wide query.
  • No check that the ids the model quotes are the ids the tool returned.

Next

  • Valid key → run the round trip. Everything else here is downstream of knowing whether the planner works.
  • GeoJSON export. The largest gap in the evidence story, and it unblocks between and along.
  • Reimplement near on top of distance — a small, obvious fix.
  • Report count alongside implied-by-area whenever fusion is detected.

S6 — Change reasoning built · never run on real pairs

Classifies each transition between two dates, because the same raw pixel difference means completely different things. A pixel diff is mostly noise and phenology; the value is in the categories.

Built

  • Transition taxonomy: phenology, succession, construction, impossible.
  • Diffs co-valid pixels only — nodata on either date is not a change.
  • Guards multi-stage succession jumps as classifier disagreement, not regrowth.
  • One-pass component counting per class pair.

Missing

  • blocked No second date exists for any tile — never run on a real pair.
  • Co-registration is assumed and it will not hold. A one-pixel shift creates a halo of fake transitions along every region edge. Single biggest threat to S6 being useful.
  • Cannot tell two dates from two model versions — retraining would read as change.
  • Phenology is two hard-coded pairs, with no acquisition date or rainfall as input.
  • Transitions are aggregated, not localised — a table, where users want change polygons.

Next

  • Get one second-date raster. Everything here is theory until then, and every impossible transition it finds is free ground truth for S1.
  • Log the segmenter version per raster — cheap now, impossible retroactively.
  • Erode boundaries before diffing, or require change components to be interior.

Suggested order of work

Roughly by value per unit of effort, cheapest first.

  1. Replace the API key and re-run the S5 round tripTwo commands; everything is staged and the index is cached. It is the only thing standing between the planner and its first measured result — and the refusal-relay behaviour is the highest-risk unknown in the repo.
  2. Promote the ground truth to a golden-set pytestThe offline answers are already computed and saved. Turning them into assertions makes the arithmetic checked on every commit, for free.
  3. Review ~50 S1 causes by handProduces the false-positive rate, which is the blocking question for S1 and a baseline for S2. The roll-up is what makes this a morning's work instead of a month's.
  4. Attach a DEMUnblocks four of the six solutions at once. Worth more than RGB for this taxonomy — dip slope, terrace, badlands and boulder are all morphology.

  6. Run any detector over S3's control setConverts a claimed 95% cost reduction into a defensible one, and replaces the placeholder budget knob with a recall target.
  7. Decide S4's output units with its consumerCheap, and it invalidates tuning work if left until after.
  8. Obtain one second-date rasterMakes S6 real, and pays S1 back in free ground truth.
