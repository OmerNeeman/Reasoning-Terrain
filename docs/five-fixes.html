question 1 · correctness

S2 mixed two scoring scales in one ranking

fixed

Your answer: “the scoring scale will be the same” — every candidate in a ranking now goes through the identical formula, whether OSM had an opinion about it or not.

A candidate with real OSM support used to score 0.7·own + 0.3·reference while a sibling OSM said nothing about kept its raw own — two different scales in one ranking, and OSM support could lose to OSM silence. The fix: once any candidate in a ranking has a real reference, every candidate blends against it — the silent ones against a neutral 0.5 stand-in, not their raw score. Silent-about-everything rankings are untouched (total == own, bit-identical, still locked in by test_s2_is_bit_identical_without_osm).

A (own 0.70, real OSM 0.30) vs B (own 0.60, OSM silent): 
# old formula
A.total = 0.58   (0.7×0.70 + 0.3×0.30)
B.total = 0.60   (= B.own — untouched by the blend)
winner  = B   ← bug: silence beat weak real support

# new formula
A.total = 0.58   (unchanged — A always had a real reference)
B.total = 0.57   (0.7×0.60 + 0.3×0.5 neutral stand-in)
winner  = A   ← fixed: real support wins

question 2 · server

The playground could be wedged permanently

fixed

Your answer: “ok add job timeout, sounds fair”

Two additions: a 600s lock-acquire timeout (a queued job now fails clearly instead of waiting forever behind a stuck one) plus a watchdog that flips a still-“running” job to failed past the same deadline; and an LRU cap (MAX_JOBS_RETAINED = 50) that drops old jobs’ ~3.2 MB in-memory report bodies, falling back to the copy already on disk. Honest limit: neither mechanism can force a genuinely hung syscall (a FIFO inside an uploaded directory, say) to release the OS-level lock it holds — that thread still leaks until a restart. What’s fixed is visibility (failed, not silently “running” forever) and a bounded wait for everyone queued behind it.

question 4 · contract

Nodata was scored as impassable

fixed

Your answer: “yeah add NaN”

The builtin provider used to zero every nodata pixel — identical to a genuine cliff or wall. It now emits NaN for valid=False ground (unmeasured, not scored) and keeps 0.0 only for ground that was measured and is genuinely impassable. A caller-supplied mask (deliberately restricting scope, not a data-availability claim) still reads 0.0 outside it. _validate now accepts NaN but still rejects ±inf; a new result.unmeasured_fraction and an extended caveat_block() surface how much of a result is actually unmeasured; tilemap.py's per-tile aggregation was fixed alongside it so a partially-NaN tile no longer round-trips into a misleading 0.0 average.

question 5 · packaging

The data files lived outside the package

fixed

Your answer: “insert into the package. alright”

examples/smart_terrain_class_ids.json and docs/class_notes.md moved into src/segmap_digest/data/, declared as package data, and loaded via importlib.resources in both class_notes.py and playground.py — in place of a path-guessing helper that only worked for an editable install. $SEGMAP_CLASS_NOTES still overrides the bundled default, for an analyst's own working copy.

found along the way · not fixed

Two things the demo turned up

Neither of these was one of the five approved fixes, and neither has been touched. Flagging them because running real commands against real data is how they surfaced, and sitting on a finding is worse than an ugly one.

segmap report --osm is accepted and does nothing

report.py has zero references to osm anywhere in the file — cmd_report never wires the flag into S2 or S4, so adjudicate() runs with no reference map and every Evidence.reference in a report run is None, silently. segmap solve and segmap playground both wire OSM correctly — the gap is specific to report.

s4_products.summarise crashes on an all-nodata crop

Hit live, demoing fix #2: a 94%-nodata leb tile with a 4 Mpx center crop landing entirely inside the nodata region raised IndexError: index -1 is out of bounds for axis 0 with size 0 from an np.percentile call on an empty array. The job failed cleanly (that part is fix #2 working correctly) — the underlying crash is a separate, pre-existing edge case.

Run it yourself

Every number above came from one of these. Nothing here needs network access except the two OSM-fetching steps, which degrade to “skipped” rather than failing the run if Overpass is unreachable.

  1. Confirm the baseline

    Full suite, from the repo root:

    pytest tests -q
# 223 passed, 1 skipped

  2. Run the real pipeline

    Produces out/demo-fixes/report/index.html — open it in a browser for the full S1–S4 report, including the three images above:

    segmap report -i data/incoming/leb --osm --max-mpx 8 \
    -o out/demo-fixes/report --chip 128

  3. Watch a real job through the playground

    Starts a local server; upload one tile from data/incoming/leb/ through the browser form, or post it directly and poll the job:

    segmap playground --port 8711
# then, from another terminal:
curl -F "file=@data/incoming/leb/tile_cropped_x3308_y3673_z0.125.tif" \
     -F "max_mpx=6" http://127.0.0.1:8711/run
# follow the Location header, or poll:
curl http://127.0.0.1:8711/api/job/<job-id>

    Finished reports land in out/playground/<job-id>-.../index.html; /jobs lists run history; a job past JOB_TIMEOUT_S (600s) reports itself failed instead of hanging.

  4. Re-run each fix's own regression tests

    pytest tests/test_osm.py -k "s2_reference_penalty or s2_renormalizes or s2_is_bit_identical" -v   # fix 1
pytest tests/test_playground.py -v                                                              # fix 2
pytest tests/test_osm.py -k scale_note -v                                                        # fix 3
pytest tests/test_tilemap.py -k "nan or unmeasured or builtin_scores_nodata" -v                  # fix 4

  5. Verify the package installs non-editably

    python -m build --wheel --outdir /tmp/rt-dist .
python -m venv /tmp/rt-venv && /tmp/rt-venv/bin/pip install /tmp/rt-dist/*.whl
cd /tmp && /tmp/rt-venv/bin/python -c \
    "from segmap_digest import class_notes, playground; \
     print(class_notes.DEFAULT_PATH.is_file(), playground.DEFAULT_CLASSES.is_file())"
# True True -- and neither path mentions this repo checkout
