segmap-digest: what goes in, what comes out, what happens in between

A Smart Terrain segmentation raster is already symbolic — the segmenter knows TerraRosa as an integer and nothing about decalcification clay. This pipeline turns that raster into representations a reasoning model can work with, and answers questions from them. No RGB imagery is involved anywhere.

Every number on this page was reproduced against this checkout on the sinai drop (20 GeoTIFFs, 31822×37535 px @ 0.496 m/px) or the synthetic fixture, and is sourced in the tables below. Nothing here is a finding about the ground — see What to trust.

1. The pipeline

Five stages. Everything left of solutions is query-independent and computed once; everything right of it is cheap.

inputon disk
A label raster — one band, one integer class id per pixel.
label raster (.tif / .npy / .png) + optional DEM + optional 2nd-date raster (S6)
▼
loaderloader.py · mosaic.py
Wire ids → dense taxonomy ids, by name.
  • Sparse wire ids 0..241 read from the ID_TO_LABEL_MAPPING GeoTIFF tag; an unknown name is an error, never folded into Unclassified.
  • Nodata mask: every 0 is no-data, and every fraction downstream is over classified pixels only.
  • A directory input is mosaicked by affine transform; mixed CRS or resolution raises rather than resampling.
  • Geographic CRS: transform.a is degrees, converted to metres from the tile's latitude.
▼
indexindex.py
Raster → two symbolic indices, because they answer different questions.
  • Region index — connected components, each with area, perimeter, compactness, elongation, mean/σ slope, elevation, aspect circular variance, and a neighbour graph with shared boundary lengths. Tells you why.
  • Chip index — a fixed grid at the detector's input size (256 px default), each chip with a class histogram, entropy, class-pair interface lengths and distance-to-anchor-class fields. The unit of spend for detection triage.
Cached. Both indices are query-independent, so they are built once and memory-mapped afterwards. On the 174.5 km² sinai mosaic: cold 24 min 24 s / 47.0 GB → warm 1.5 s / 1.5 GB, 7.2 GB on disk. Keyed on input paths, mtimes, sizes, GSD, crop window, --min-px, chip size, anchor classes and a schema version — a stale cache misses rather than answering. Every command says on stderr which cache it used.
▼
digestsdigests.py
Index → text a model can read. TSV, not JSON — roughly 2–3× fewer tokens for the same content, with the legend emitted once instead of repeating key names per row.
l0 · class histogram l1 · N×N grid l1q · quadtree l2 · region table l3 · adjacency graph chips · chip index
▼
solutionssolutions/
Six map-consuming solutions over the shared index. Numbers come from code; the model, where it appears at all, chooses which question to compute, never the arithmetic.
S1 audit S2 adjudicate S3 attention / triage S4 products S5 query S6 change
▼
outputsstdout / files
TSV on stdout, product PNGs, a policy JSON, and one self-contained HTML report that runs the whole thing end to end.
HTML report worklists & verdicts ranked chips + policy product rasters structured answers change events

The LLM is never in a per-item loop. For triage the model compiles a query into a small cached policy and a deterministic scorer applies it to millions of chips; amortised reasoning cost per chip ≈ 0.

2. Inputs — exactly what is accepted

One band, one integer per pixel, and a way to know what the integers mean. Everything else is optional. The traps below were all found on real exports.

WhatAcceptedThe trap, and what the code does about it
label raster single-band GeoTIFF, .npy, single-band PNG A colourised RGB export is refused, not guessed at: "is a 3-band image. This tool wants a single-band label raster, not a colourised one — recovering class ids from RGB is lossy and ambiguous." Colourised maps are for humans; asking a VLM to read exact colours off a 47-entry legend is a task VLMs are bad at.
class ids ID_TO_LABEL_MAPPING GeoTIFF tag, else --classes ids.json On the wire the ids are sparse, 0..241 — not the dense 0..46 of taxonomy.py. The tag is read automatically and mapped by name. A name the taxonomy does not define is an error, not something to fold into Unclassified. A raster value with no entry in its mapping raises too. examples/smart_terrain_class_ids.json is the sinai drop's mapping, 47 entries spanning ids 0–241.
nodata read from the GeoTIFF header nodata = 0 collides with Unclassified's id. The two are not distinguishable in the file. Every 0 is treated as no-data, every fraction is over classified pixels only, and the report says how much was excluded. If the segmenter genuinely emits Unclassified, that class is being thrown away and the exporter needs to give nodata a value of its own.
georeference any CRS the file declares A geographic CRS means transform.a is degrees. A 0.5 m/px export in EPSG:4326 has a transform of ~5e-06; reading that as metres made every area in the report ten orders of magnitude too small. geotiff_gsd() now converts from the tile's mean latitude.
a directory adjacent GeoTIFFs, mosaicked Placement comes from the affine transforms. Mixed CRS or pixel size raises rather than resampling — resampling a label raster invents classes at every boundary. Mosaic, don't tile: regions are connected components, so per-tile analysis cuts one wadi across four tiles into four regions with four wrong areas and four wrong neighbour lists. The mosaic is cropped to the bounding box of actual data, which drops no labelled pixel.
DEM (optional) --dem file.tif|.npy Attaching one switches on slope, aspect and every morphology check. No AOI here ships one — see §5. For this taxonomy the DEM is worth more than RGB: dip slope, terrace, badlands and boulder field are all morphology.
2nd date (optional) --second later.tif A second-date label raster over the same ground, for S6. Without one, S6 runs against a synthetic second date off the fixture.
too big? --max-mpx N Takes a centred crop of at most N megapixels at full resolution — never a stride, because striding a label raster deletes every feature narrower than the stride (roads and wadis are 1–4 px on sinai). The window, its share of the extent and its share of classified pixels are stated in every output that carries it, including the question handed to the model.

3. Outputs — the full menu

Each row: the question it answers, the command, and its honest status. $T is a tile or a directory of tiles.

OutputQuestion it answersCommandStatus — what it is really worth
HTML report "Show me the whole pipeline on this AOI, on one page." segmap report -i $T -o out/aoi Works. 17 s on the fixture. Writes index.html plus PNGs; every section states what it assumed. The fastest way to see what the thing does.
The six digests "Give me a representation of this map at a token budget I can afford." segmap digest l2 --limit 40
segmap compare		 Works. Costs in §4. Every --limit emits # NOTE: N omitted — a cap that reads as "this is everything" is how you ship a wrong answer, and a test enforces it.
S1 worklist
+ coverage statement		 "Which labels contradict their context, slope or geometry — and what did you not check?" segmap solve s1 -i $T --budget 8 The coverage statement is the trustworthy part; the findings are a worklist, not a verdict. Findings roll up by root cause, so the sinai mosaic is 26,592 findings → 178 decisions. But there is no measured false-positive rate — that is S1's own blocking question, needing ~150 reviewed regions.
S2 verdicts "This region is suspect — what is it, or is it undecidable?" segmap solve s2 -i $T --region 245 Verdict vocabulary is KEEP / SWITCH:<name> / UNDECIDABLE-NEEDS-<data>, with a scored candidate table. Abstention is a first-class output and is designed to fire often: Limestone/Dolomite/Nari are not separable without a geological map, and a system that picks one confidently manufactures corruptions. Net gain is corrections minus corruptions and can be negative. With no DEM the morphology column is unscored, so most verdicts here rest on context alone.
S3 ranked chips
+ policy JSON		 "Which chips are worth sending to an expensive detector?" segmap solve s3 -i $T --policy vehicles --chip 128
… --save-policy p.json		 Runs. Reports cost reduction, a 3% control set drawn from rejected chips — the only unbiased recall signal you will ever have — and warns in its own output that "score captured" is prior mass, not recall. Recall needs detector outcomes, which do not exist yet.
S4 product rasters
PNG + per-region tables		 "Can I drive there / hide there / will it pool / will it burn?" segmap solve s4 -i $T --product trafficability --wet --regions -o out/traf.png Four products: trafficability, concealment, drainage, fire_fuel. Each a float raster in [0,1] plus per-superclass means and an optional per-region table. Half of it is inert without a DEM — measured, see §5. No LLM in the runtime path; a model helps author the lookup tables, never evaluate them.
S5 structured answers "How many, how much, how far, what can I reach?" segmap solve s5 -i $T --query "count House minarea 40" The most solid surface here. Six verbs — find count area distance corridor describe — and every result carries the region ids it was computed from, so any number can be re-derived. Four statuses: ok, empty (a measured zero — a real finding), unanswerable (explicit refusal in words: vehicle type, building function, fence presence, anything about colour — an empty table saying "none found" would be a wrong answer), and error.
S5 natural language Same questions, asked in prose. segmap ask -i $T "How much of this tile is bare rock?"
segmap tools		 Never exercised against the live API. The six verbs are given to the model as tools and it plans; it cannot state a count, area or distance that did not come back from a tool call, because it has no other way to see the raster. The answer is followed by the call log and every entry is a solve s5 string you can rerun. segmap tools prints the surface with no SDK and no key. --digest is the un-grounded path — treat its arithmetic as an estimate.
S6 change events "What actually changed between two dates — and what is just phenology?" segmap solve s6 -i $T --second later.tif Runs. Categorises each transition — succession, construction, infrastructure, phenology, impossible — and reports the share that is plausibly real change. A Limestone→Dolomite transition is reported as impossible, i.e. a label error, not a landslide. Co-registration is the untested threat: the null test and the 1-px-shift test have not been run.

4. The representation ladder

Measured by segmap compare. The fixture column is a 1024×1024 tile at 0.3 m/px with 1,583 regions; the mosaic column is the whole sinai AOI — 1194 Mpx, 133,976 regions.

leveltokens, fixturetokens, sinai mosaicwhat it is / good for
raw786,432895,829,077The label raster as text. Never do this.
l0371398Class histogram. Composition, sanity checks. Free at any scale — it scales with class count, not area.
l12,0071,541N×N grid, top-3 classes per cell. "Where is what." Free at any scale — fixed grid.
chips538425,882Fixed-grid chip index — the unit of spend for detection triage. Cheap per chip, but it scales with chip count: 1,024 chips on the fixture, 18,104 on the mosaic. Not free at AOI scale.
l1q10,9161,735,351Quadtree — uniform areas collapse to one token. Spatial structure, compressed. Compresses far harder on a clean map than on this noisy fixture.
l336,5341,701,818Region adjacency graph. Connectivity, corridors.
l247,9083,047,077Region table with terrain attributes — the workhorse for audit and adjudication on a tile, and unusable at AOI scale.

Two things that table makes obvious:

  • l0 and l1 are effectively free at any size. Start there and only descend when the question needs it. chips is free on a tile but is 425k tokens on the mosaic.
  • l2/l3 scale with region count, not tile size, so a fragmented map is what makes them expensive. --min-area and --limit are the levers and both report what they dropped. At 3.05M tokens, sending l2 for the sinai mosaic is not an option at any price — which is the whole reason the S5 verbs compute over the index instead of handing the model a table.

5. What is trustworthy, and what is not

Trustworthy: everything counted, measured or connected-component'd from the label raster — class fractions, areas, region counts, adjacency, pixel-to-pixel distances — plus every refusal and every abstention, which are enforced in code rather than left to a prompt.

Not trustworthy — read before quoting any number from this system

  • There is no DEM on any AOI here, so every slope reads 0.0 — a valid-looking number meaning "unmeasured". This switches off roughly half the taxonomy. Consequences, all measured on the sinai tile:
    • corridor DirtRoad vehicle wheeled returns 99.0% of the classified area reachable. The slope term is inert and the tile is 68% Rendzina and 13% DryGrassland, both scored as easily passable, so almost everything connects to almost everything. Arithmetically correct, analytically useless. On the fixture, which has a DEM, the same query returns 63.5%.
    • S1's substantive coverage is 3.0% of classified area on the sinai mosaic (15 of 33 classes present; 1.4% and 8 of 20 classes on the single tile). The other 97% is unexamined, not clean. The slope and aspect priors abstain rather than score against zeros.
    • Half of S4 is inert. Measured on the sinai tile: drainage returns p10 = p90 = 0.60 — a constant with a binary wet-class bump, carrying no information; concealment means 0.00 across soil, rock and road, i.e. 98% of the tile, because both its relief term and the canopy of the classes present are zero. Only trafficability and fire_fuel vary at all, and trafficability degrades to a pure per-class lookup.
  • The class semantics are under review. The model uses Rendzina as a catch-all for pale bare soil: it is 64.9% of the sinai mosaic, against 2.55% for every chalk and marl class combined. The class owner has confirmed these are surface soil types, not genetic units — which invalidated four textbook co-occurrence priors that had manufactured 10,788 of 41,669 findings as false positives. The definitions in taxonomy.py are a starting point pending expert review, and they are the text every piece of reasoning here runs on.
  • The live LLM path has never made a real request. anthropic is installed and imports, but there were no credentials on the machine this was written on, so not one request has been made to the API. Treat the first live run as a test of this repo, not as an answer.
  • Every heuristic constant in solutions/ is a guess. They are grouped at the top of each module, named, and tabulated in each solution doc with a "where this should actually come from" column. Two exceptions are marked as measured, not guessed: S1's speck window (32–128 resolution cells) and the min-area floor's effect. Everything else — vehicle surface thresholds, canopy values, severity bands, enclosure shares — is invention. Do not treat any number they produce as a finding.
  • Counts are not verdicts. S1 reports 26,592 candidate findings on the mosaic with no measured false-positive rate. S3 reports "score captured" which is prior mass, not recall. S6 has not been run against its own null test.

6. A worked example

The real thing, end to end, on one sinai tile. From QUICKSTART.md §4, reproduced against this checkout — the # input: and # using cached stderr lines are elided.

Set the tile once

T=data/incoming/sinai/tile_cropped_x802_y847_z0.5.tif
segmap index -i $T          # 29 s, once — 11,058 regions, 1,024 chips

What am I even looking at?

Two-thirds Rendzina. Arid rangeland with dirt tracks, no settlement.

How much dirt road is there?

$ segmap solve s5 -i $T --query "area DirtRoad"
# area_m2: area DirtRoad
= 40,593.83
# evidence: region ids 36, 34, 20, 18, 28, 16, 19, 17, 32, 29, 38, 31, 25, 33, 37, 21, 30, 26, 24, 27, 22, 23, 35

4 hectares of track across 23 regions on a 16.6 km² tile. This is the arithmetic that was ten orders of magnitude wrong before the geographic-CRS fix. The region ids are the receipt.

Now ask it something it cannot answer

$ segmap solve s5 -i $T --query "find TerraRosa slope > 10"
query error: no DEM is attached to this tile, so every region's slope is unmeasured (stored as 0.0). A slope filter cannot be applied; attach a DEM with --dem and ask again

$ segmap solve s5 -i $T --query "count Fence"
query error: 'Fence' is outside the 47-class vocabulary: there is no fence class; a fence is also sub-metre wide and would not survive segmentation at this GSD

$ segmap solve s5 -i $T --query "count Car"
# count: count Car
= 0.00

Three different kinds of "no". The first abstains because the input is missing. The second refuses in words, because an empty table saying "no fences found" would be a wrong answer rather than a missing one. The third is a measured zero — Car is in the vocabulary, so this is a finding about the ground. (The tool layer returns that third case as status: empty with the sentence spelled out; the bare CLI renderer does not repeat it.)
